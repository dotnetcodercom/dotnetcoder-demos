# Angular 22.2.1 custom srcset — independent browser proof
Related article (planned canonical URL; the draft may not yet be public): https://dotnetcoder.com/custom-ngoptimizedimage-srcset-angular-22-2-1/

## Prerequisites

Node 24 and npm; Internet access for pinned dependency and Chromium downloads. Linux may need Chromium OS libraries.


The same standalone component runs against original npm packages pinned to **22.2.0** and **22.2.1**. It checks the initial DOM attribute and actual Chromium `currentSrc`, at device pixel ratios **1** and **2**, for three cases:

| Case | Angular 22.2.0 | Angular 22.2.1 |
| --- | --- | --- |
| `[srcset]` + `disableOptimizedSrcset` | No DOM srcset; fallback image selected | Custom string reaches DOM; matching 1x/2x image selected |
| `[attr.srcset]` + `disableOptimizedSrcset` | Works | Works |
| `ngSrcset="1x, 2x"` with the image loader | Generated candidates work | Generated candidates work |

All four version/DPR combinations passed on Chromium **141.0.7390.37** with Node **24.19.0**. The shared fixture uses Angular JIT and esbuild, avoiding a full CLI scaffold; the real `NgOptimizedImage` directive runs in the browser. Both dependency lockfiles are included.

Images are local PNGs with illustrative query tokens, not a real signed CDN or authentication integration. The test does not measure LCP, bandwidth, performance, dynamic srcset updates, or compatibility in other browsers. A 22.2.1 fix is not evidence that every custom-srcset configuration is supported.

## Run

Prerequisites: Node 24 and npm. Dependency and browser installation require Internet access; the proof itself uses a temporary loopback HTTP server and no external account.

PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Verify.ps1
```

Linux/macOS:

```bash
npm ci --no-audit --no-fund
npm --prefix versions/22.2.0 ci --no-audit --no-fund
npm --prefix versions/22.2.1 ci --no-audit --no-fund
node build-matrix.mjs
npm run verify
```

On Linux, Chromium may require OS libraries. Do not treat a missing-browser or missing-library error as an Angular failure.

The verifier closes the browser and local server when it finishes. Results and four screenshots are under `evidence/`. `receipt.json` records exact versions, assertions, selected URLs and browser errors. A failing assertion produces a FAIL receipt and a nonzero exit code.

The browser bundles are generated by `build.mjs` from `fixture.ts`; edit the shared fixture rather than a generated version copy. No Angular framework source is patched.
